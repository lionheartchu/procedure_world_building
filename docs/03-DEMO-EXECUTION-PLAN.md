# Residual Ecology — 分阶段 Demo 执行计划

版本：2026-10-17 · 实施建议 v1  
阅读前置：[交接说明](01-PROJECT-HANDOFF.md) · [完整变化逻辑](02-ECOLOGICAL-LOGIC.md) · 五张 reference  
目标：在现有整合世界中，逐步验证可感知的材料循环、共同身体和 emergent core。

## 1. 实施原则：固定行为目标，开放技术路线

本计划约束的是因果关系、空间关系和可观察结果。Agent 可以选择合适的网格变形、预制形态混合、粒子、场、图结构、贴花、纹理、shader 或组合方式。没有必要为每个概念建立一个独立复杂系统。

| 必须保持 | 可由 agent 判断 |
|---|---|
| 与现有 Explore 共享世界；保护已有工作 | 模块拆分、更新频率、状态组织和开发开关 |
| 释放、沉积和利用之间有实际状态联系 | 用粒子、场、事件或其他表示维护材料 |
| 新生长读取历史改变，而非固定刷新 | 形成规则、候选位置算法、形态生成方式 |
| 多个居民的结果形成持续的地表组织 | 地表组织用几何、纹理、隐式形体或混合呈现 |
| Core 是嵌入地表、由多轮历史形成的区域 | 增密判据、轮廓、局部折叠的生成策略 |
| 观众在合理观看尺度下能辨认变化 | 相机、演示速度、构图、对比度与轻量诊断工具 |

现有技术栈是出发点。优先复用；若需要明显的架构调整，说明原因、成本和一个较小替代方案。不要仅为这次 demo 无故重写渲染器或建立第二套世界。

## 2. 本轮默认范围与交付层级

建议选取现有世界中的一小片连续区域：约三个可辨认居民、两个材料可能停留的位置，并保留少量邻近形态作为空间参照。数量可因构图调整，但不能退回不可辨认的单片膜。

| 阶段 | 交付重点 | 到这里可以宣称什么 |
|---|---|---|
| 0 | 现状核对与范围确定 | 找到了可实施的入口 |
| 1 | 可读的形态与地表关系 | 视觉过程和空间位置成立 |
| 2 | 真实释放、沉积、利用与跨居民影响 | 局部生态循环成立 |
| 3 | 多代残留成为持续的共享组织 | 开始形成共同身体 |
| 4 | 嵌入地表的 core 从历史形成，并缓慢受影响 | 整体身体的长期演化成立 |
| 5 | 可选回馈、交互与更长期连续性 | 按实际完成项分别说明 |

**建议给 coding agent 的第一轮任务：推进阶段 0–2，提交一个可观看的局部 demo 后评审。** 阶段 3–4 是接下来的主目标，不应因局部循环跑通而被遗忘。局部 demo 不等于“整个世界已经作为生命体成立”。

常规检查、修复和调参不需要每一步都停下来确认。优先在阶段 2 和阶段 4 两个有具体结果的节点评审；遇到需要改变概念方向或大幅扩大范围的阻碍时，提前说明。

## 3. 阶段 0：确认真实起点

### 具体要做

- 确认正在使用 `procedure_world_building` 的目标 checkout，读取项目自身说明与本地未提交修改。
- 查找用户报告的 lifecycle 实验；确认是否仍存在、能够运行、对应哪些文件和开关。
- 区分初始 History、实时材料记录、Growth 播放和真正的生命周期更新。
- 确认 terrain、resident、transport、deposit 的位置/坐标与显示高度关系；只修复阻碍本轮闭环的问题。
- 保存一个可复现的起点，挑选一个正常距离看得清的小区域和默认观看角度。

### 交付 / 通过条件

给出简短对照：已有机制、能复用什么、本轮缺口、将使用的简化、首个 demo 的范围。清楚标明尚未确认的前一 agent 报告。

这一阶段不是长时间全面重构。没有实质阻碍时，继续做阶段 1，不要只输出审计报告就结束。

## 4. 阶段 1：先把形态变化和地表关系做得可读

参考图：02 为主，03 为辨别原则，04 为地表内部关系。

### 具体要改

- 将演示区域调整到可读尺度；保留至少一位一直存在的邻居作为参照。
- 给主居民做连续的展开、伏下、释放、留下低伏轮廓的形态过程。复用现有形态语法，避免主要靠增加孔洞。
- 为沉积设计贴地表现，区别于普通尘埃、漂浮碎片和活跃膜面。
- 放出“残留已在，新生长尚未出现”的可观察时间段。
- 让新形体从改变过的地表局部展开，形态或位置与前一代有可解释差别。
- 用薄层连续性表达共享身体的空间可能性；这个阶段的静态底层或预置姿态必须标为视觉样机，不能宣称由历史自动长成。

### 交付 / 通过条件

短录像或一组固定视角画面，可以看出来源、落定位置、等待、新生长及旧轮廓。允许先手动切换状态检查形态；在阶段 2 完成前，不把这段样机称为模拟结果。

默认视角应能看清关键变化，不依赖 inspector 数值或极端放大。若不清楚，先改尺度、节奏或对比，不继续堆叠机制。

## 5. 阶段 2：让可见过程由真实材料反馈驱动

参考图：01 与 02。

### 具体要改

- 将来源减少、碎片迁移、落定、可用残留和后续生长接为实际状态变化。
- 让释放材料进入可读取、可见的地表记录；运行中的改变和初始 History 在逻辑上可区分。具体存储结构不限定。
- 至少让一部分结果影响来源以外的居民或位置。可以是邻居局部延展，也可以是不同位置的新生。
- 生长利用材料时，减少相应可用残留；同时保留一部分旧轮廓或继承的结构影响。
- 后来者至少读取一项可解释的历史结构，例如附着边缘、方向或与旧组织的关系；不只读取数量后换随机种子。
- 没有合适形成条件时允许等待或空置，移除原样重生的保底逻辑。
- 确保循环自主发生，并让居民生命周期错开。提供开发用重置、暂停、加速或等效控制。

### 最小因果检查

在相同起点、相关随机性和演示输入下，对比：

1. 正常沉积参与后续生长。
2. 材料仍可被展示，但生态反馈被关闭，或在使用前只移除新增残留的影响。

说明结果具体差在哪：位置、展开量、附着方向或是否生成。对比应尽量保持无关过程一致；不能通过更换整个世界种子制造差异。

再做一次来源/去向检查，确认没有同一材料同时留在居民、碎片、沉积和新生长中重复可用。沿用现有测试工具即可，无需为了展示新增庞大测试框架。

### 交付 / 通过条件

- 一个普通视角可读、能重置重演的短 demo。时长可先以数分钟试调，按可读性决定，不规定固定秒数。
- 至少一轮“原形体结束 → 地方改变 → 后来者受影响”，同时有其他居民持续存在。
- 一份简短因果说明和对照证据；明确时间加速、预设条件、简化流动及会话内限制。

**到这里先评审局部循环。** 如观众仍只能看出“物体消失后换了一个”，不要进入大范围扩展。

## 6. 阶段 3：让不同居民的结果形成共同身体

参考图：04 的形成过程，05 的前两格。

### 具体要改

- 让来自至少两个居民、跨至少两次变化事件的残留在同一地方接触、整合。
- 为共享组织建立慢于居民的连续状态；个体结束不能把整片组织随之删除或重建。
- 让连续组织嵌入地表，与居民基部有可信的空间连接。
- 给它一个实际作用：影响附着、局部可用材料、连接连续性或后续生长。选择一项做清楚即可。
- 明确“残留怎样被纳入组织”的规则，例如相接、局部重组和活跃连接的参与；不需要新建一套复杂生物繁殖模型。
- 处理最重要的空间反馈：居民或组织明显移动/退缩后，相关附着位置和局部作用应随之更新。空气、光、遮挡可以分步处理，避免宣称尚未发生的反馈。

### 交付 / 通过条件

用同一块地展示：多个来源留下痕迹，后来形成连续结构，随后一代居民消失，结构的一部分仍留着并影响后来者。

能指出：哪部分来自哪次变化、哪里已经整合、保留了什么功能。需要看见共同身体的连续性，而不只是给每位居民各自增加一块底座。

这一阶段可以用局部剖面帮助诊断，但正常地表视角也应有足够线索，不能只有剖面模式才看得出身体存在。

## 7. 阶段 4：Core 从历史里形成，并在更慢尺度上受影响

参考图：04 全图、05 的前至第三格。

### 具体要改

- 选择一个有明确空间理由的演示位置，让多轮残留、连接和沿用逐渐造成局部增密。
- 从共享组织的现有表示中形成 core 区域；不在阈值到达时突然放入独立核心物件。
- 表现为地表内部的低伏叠层、折合或交织，边缘延续到较稀薄组织。允许采用便宜的视觉近似，但近似应读取实际形成状态。
- 保持表面居民仍可独立更替；其结束不立即重置 core。
- 实现一种缓慢的受影响方式：长期更新不足后，部分组织变薄、松弛或连接减弱。具体“维持”机制由 agent 提出，不能简单用居民数量当全局血量。
- 区分短期的材料回流和长期的维持不足。释放材料可能先补充身体，并不要求一发生死亡就立即变弱。
- 若为演示压缩多代时间，可以预演历史或加速；记录其来源，不用手工造型冒充自然形成。

### 交付 / 通过条件

展示至少三个可追溯状态：尚未增密的组织、经过历史形成的 core、居民减少一段时间后的改变。

至少做一个针对来历的检查：改变相关材料停留/整合历史，core 的形成位置、程度或形态应相应变化。无需为了“涌现”追求不可复现的随机性。

画面需满足：它属于地表身体，仍与外围相接；不是埋在地下的球体。没有 core 的其他位置仍可发生局部循环。

**到这里再评审整体方向。** 重点问题是：“居民更替时，是否能认出那个持续存在、缓慢改变的身体？”

## 8. 阶段 5：按价值单独增加，不作为前四阶段的依赖

这些是独立候选，不要求一次全部完成。

| 候选 | 要增加什么 | 必须说明什么 |
|---|---|---|
| 向居民回馈 | 共享组织或 core 缓慢提供材料，支持局部后续生长 | 来源减少、接收者获得什么；不是凭空供能或保证复活 |
| 环境干预 | 用户改变局部流动或其他一个条件，生态自行响应 | 自主循环仍存在；用户不是逐个下达生死命令 |
| 跨会话连续性 | 保存真实的动态状态或可重演事件，使历史可继续 | 保存什么、如何恢复、参数改变是否重置；区别于配置收藏 |
| 扩大空间 | 将规则带到更多居民/群落 | 局部密度、可读性和性能是否仍成立 |
| 细化时间线索 | 进一步区分年龄、状态和地方历史 | 不把更多孔洞、更大尺寸或更多居民等同于更老 |

图 05 第四格对应第一项。若采用能源机制而非材料回馈，应先提出一个有来源和消耗解释的方案，再决定是否值得增加复杂度。

## 9. 全程适用的工程边界

- 保留原有可工作的世界和 Studies；优先可关闭的开发入口，不增加独立公共 tab。
- 先检查并保护未提交修改，不覆盖前一 agent 的工作。
- 预计算初态、运行历史与展示动画要能在概念上区分；不要求它们必须存在于三个固定文件或数据表。
- 生命周期状态改变后，不应无意触发整个世界重生成并清空历史。
- 材料落点、显示表面、组织附着要使用一致的空间依据。先解决影响 demo 的错位，其他已有问题留在 backlog。
- 将开发 inspector、剖面、材质诊断与正常体验分开；不要把后台术语和控制堆到观众界面中。
- 控制碎片、历史记录和组织细节的增长；允许简化与有限保留，说明其对记忆的影响。
- 运行项目已有的必要构建/检查，补充与本轮风险直接相关的验证。不要默认重做整套全世界像素测试。
- 未经另行授权，不提交、部署或发布；本轮以可审阅的本地改动和 demo 为交付。

## 10. 每次里程碑报告的最小格式

1. **实现了什么**：列出实际发生的机制，避免只写“更有生命感”。
2. **如何观看**：入口、默认视角、重置与加速方式。
3. **因果证据**：一条具体事件，以及关闭相关反馈后结果怎样不同。
4. **与 reference 的关系**：遵循了哪些关系，哪些地方选择了更可行的视觉表达。
5. **简化与缺口**：预置内容、静态部分、未更新的邻接系统、持久化边界。
6. **下一步**：只推荐一个最需要推进或评审的方向。

## 11. 可直接发给实现 agent 的任务说明

> 请基于当前整合后的 Residual Ecology 制作一个分阶段 demo。先读 `01-PROJECT-HANDOFF.md`、`02-ECOLOGICAL-LOGIC.md`、本计划及五张 reference；检查实际仓库、未提交修改和已有 lifecycle 实验。图像是设计研究，不是现有功能证明，也不是要求逐像素复制的模型。
>
> 本轮默认推进阶段 0–2：在同一世界的一小片区域中，让多个居民错开变化；某位居民释放的材料真实落定、形成可见且可读取的残留，并影响另一处或另一位居民的后续生长。生长应利用材料，保留可辨认的旧痕迹；无合适条件时允许等待。请特别保证普通观看尺度下的可读性。
>
> 长期方向是居民在地表表面更替，共享身体与 emergent core 在地表内部缓慢形成、延续和重组。阶段 1 可以检查这种空间关系，但不要提前把预置造型称为涌现 core。阶段 3–4 再逐步实现多代结果的整合。向居民回馈是后续候选，本轮不强制实现。
>
> 技术路线由你结合现有代码决定，优先复用，允许合理简化。不要只倒放动画或固定重生；不要为演示另造一套长期维护的世界。先简短说明复用点、缺口和拟采用的实现，然后继续完成本轮范围；有重大架构或概念阻碍时再提出。用最小可复现对照证明因果，交付观看方式、短录像或固定视角证据，以及真实限制。完成阶段 2 后报告供评审，暂不扩大至全世界，不提交或部署，保留无关工作。
