版本：2026-10-17 · 设计交接 v1  
适用对象：项目作者、后续 Chat、负责制作 demo 的 coding agent  
本轮交付：设计文档与执行建议；未修改项目代码、提交或部署。

## 1. 先读这一页

**项目要从“有许多居民的生态景观”，发展为“居民在表面更替、共同身体在地表内部持续重组的世界”。**

居民会生长、展开、退缩、脱落和结束。它们留下的材料进入环境，改变其他居民的生长条件；其中部分残留经过多轮沉积、连接与重组，形成与地表连续的共享组织。组织在某些地方逐渐增密，成为 emergent core。Core 是循环留下的结果，并继续受到循环影响。

Core 的存在尺度比单个居民更长。它可以变薄、松弛、局部退化和重组，但不会因为一个居民结束就立即消失。向其他居民回馈、支持后续生长是用户感兴趣的未来方向，具体机制尚未确定。

**先做一个看得清、因果成立的小范围 demo，再扩大范围。** 观众需要看到环境确实被过去改变；仅有动画或后台数值差异都不足以完成目标。

## 3. 已确认的设计方向

1. **一个世界。** 延续整合后的 Explore，不再增加独立的公共实验 tab 或另一套长期维护的世界状态。开发诊断视图可以存在。
2. **生命周期先于新物种。** 复用已有 membrane、structure、fragment、residue、branching 等视觉材料，把它们之间的关系做出来。
3. **居民与身体的时间尺度不同。** 居民更替较快；共享组织和 core 缓慢改变，跨越多代居民延续。
4. **Core 从历史中形成。** 起初没有预置的运输中心；不把所有材料强制吸到一个固定点。
5. **Core 嵌在地表内部。** 它是与土壤/地表连续的较密组织区域。表面的居民不是一群围绕独立核心摆放的装饰物。
6. **循环保留影响。** 新生命受过去留下的条件影响，不原样复原前一代；局部也可以暂时没有新生长。
7. **世界自主变化。** 用户不操作，循环也发生。交互以后可以干预环境，不是启动生命的唯一开关。
8. **视觉保留既有语言。** 紫罗兰、淡紫、珍珠白；光滑、连续、半透明；柔软地表、微妙透光。观众能感知关系，但不必看见后台指标。

“不会死掉”在这里指长时间的连续性，不是绝对不可损坏、永远不变或无条件恢复。

## 4. 尚属提案，不能当作用户已确定的机制

| 问题 | 当前建议 | 仍待决定 |
|---|---|---|
| 共享组织如何维持 | 活跃连接和局部更新维持组织，长期交换减少后逐渐衰弱 | 维持量怎样定义、代价怎样表达 |
| Core 如何回馈 | 可先考虑储存的材料缓慢支持相邻生长 | 是否采用这一机制；是否真的需要独立“能量”系统 |
| Core 怎样识别 | 多轮历史形成的连续、稳定、增密区域 | 具体指标、数量、位置变化、最低形成条件 |
| 形态怎样显示年龄 | 重组边缘、附着痕迹、层次可作为候选 | 怎样与当前姿态、居民数量和大小区分 |
| 用户怎样干预 | 之后研究局部环境变化 | 不在第一轮加入完整操控/游戏系统 |
| 历史跨会话保存 | 长期世界希望具有连续性 | 第一轮可只做会话内；必须明确重置边界 |

这些提案需要 agent 提出最小、可解释的实现；不应一次性全部加入。

## 5. 当前实现状态：分清三个证据层

### A. 2026-10-17 读取到的公开仓库文档

当前讨论的仓库是 [lionheartchu/procedure_world_building](https://github.com/lionheartchu/procedure_world_building)。README 与 architecture 文档仍描述：

- 地形、水道、预计算 sediment History、colony placement、组织/光/空气之间已有单向依赖。
- Explore 与 Scatter 共享世界状态；Studies 保留原研究视图。
- History 是预计算记录；Growth 主要播放已生成形态的出现。
- 公开文档尚未把持续生命反馈、共享身体和 emergent core 描述为已实现。
- 文档列出的技术栈是 React、Vite、react-three-fiber/three.js、JavaScript 和 GLSL。这是当前背景，不是本计划锁定的实现方案。

**本次做了文档核对，没有在用户工作区运行当前代码。** Agent 必须检查自己的实际 checkout、分支和未提交修改。

### B. 用户贴出的前一轮 agent 实验报告

报告称，一个关闭为默认状态的实验实现了：一位居民衰退并释放可追踪材料，材料写入独立的 live residual record，下一代读取这个记录。报告包含 A/B、消融与确定性检查。这些结果是**前一 agent 的报告，本次未独立复现**。

报告提到的查找线索：`lib/lifecycle.js`、`LifecycleLayer.jsx`、`LifecycleInspector.jsx`、`App.jsx`、`ScatterLayers.jsx`；开关包括 `?lifecycle=1`、`feedback=0`、`lifespeed=8`。实际路径、参数和是否仍存在，以本地代码为准。

其主要问题：对象太小；衰退主要靠开孔；沉积没有画出来；邻近组织、光和空气障碍基本静态；残留不被消耗也不衰减；无合适位置时会原样回生；会话/视图切换可能重置。用户因此要求暂停直接迭代，先设计图解。

## 7. 最容易再次走偏的地方

- 做成“一片小膜开洞、消失、原样刷出”。
- 只有粒子特效，没有能被读取的沉积；或只有后台记录，没有可见的地方变化。
- 新膜长出来了，但原材料没有被利用，导致无限堆积和膨胀。
- 只做邻居之间的循环，忘记它们共同形成的长期身体。
- 用埋在地下的球体、发光心脏或独立雕塑替代地表内部逐渐增密的组织。
- 把居民死亡即时换算成 core 扣血，忽略材料回流与长期维持的不同作用。
- 全场同步呼吸/变亮，却没有任何共享状态或因果联系。
- 把图中的剖面、金色标记、纸面排版永久放进体验。它们用于解释，不是必须照抄的最终视觉。
