# Residual Ecology — Aesthetic Language

> Shared visual and experiential language for **Residual Ecology**, which
> began as the procedural world-building branch of *Trace Habitat*.
>
> This file is intentionally **not** a project brief, feature list, or world-logic document.  
> It exists to keep procedural experiments visually and experientially coherent while allowing the world systems to diverge.
>
> **Written in September 2026, reconciled in October 2026.** The direction
> has since moved: dreamy and softly luminous, predominantly violet,
> lavender, lilac and pearl, and never fixed by going darker or bluer.
> Where an earlier rule differs, it has been revised in place and marked
> *(October)*. These are principles to test work against, not fixed
> requirements; the direction is still exploratory.

---

## 1. Core Mood

The world should feel:

- dreamlike
- hazy and softly luminous *(October)*
- quiet
- spatially deep
- at most slightly uncanny: strange, never dark or menacing *(October)*
- alive without being busy
- soft, but not cute
- futuristic without looking like generic sci-fi
- organic without imitating realistic nature
- contemplative rather than game-like

The experience should suggest a place that **exists on its own**, with the user temporarily entering it.

### Primary rule

**Everything moves. Nothing moves fast.**

Slow drift, long-period motion, gradual emergence, lingering after-effects, and soft transitions should dominate.

Avoid snappy game feedback, rapid animation, hard cuts, and hyperactive procedural motion.

---

## 2. Visual Value Structure

The strongest visual principle is:

**atmospheric depth + soft luminosity + one or a few restrained luminous systems**

*(October: the September version led with dark silhouettes. Reviews found
that darkening made the scene muddy rather than deep. Depth comes from
layering and light, not from blackness.)*

The scene should not be evenly illuminated.

Use:

- soft, mid-value foreground / midground silhouettes
- strong depth falloff
- haze and fog to separate spatial layers
- reflected light
- sparse emissive accents
- one dominant luminous landmark or environmental source when appropriate

Far geometry does not need high detail.  
Depth should come primarily from **layering, fog, scale, and light contrast**.

---

## 3. Color Language

### Base palette

Predominantly **violet, lavender, lilac and pearl** *(October)*:

- **Deep indigo** — background / sky; the darks stay violet, not black or blue  
  `#0B0E1E`

- **Grey-violet** — mid-value structure  
  `#3A3A5C`

- **Faded lavender** — distant surfaces / reflections / soft atmospheric accents  
  `#8D86B8`

- **Lilac and pearl** — luminous matter, membranes, haze, soft highlights,
  with subtle iridescence *(October; replaces "pale lavender / blue-white")*

### Living trace color

- **Moonlit mint** — a rare, optional accent for something active *(October)*  
  `#9FE8C8`

### Scarcity rule

Mint is **not** a general accent color, and it is not required.

If it is used, use it only when something is:

- alive
- active
- growing
- carrying energy
- transmitting a trace
- responding to another system

If everything glows mint, the color loses meaning.

### Avoid

- generic “AI blue”
- neon cyan everywhere
- saturated purple gradients
- rainbow procedural palettes
- bright green vegetation by default
- harsh black-and-white contrast
- muddy grey-blue scenes with no luminous hierarchy
- fixing muddiness by darkening, or by shifting toward ultramarine, icy blue
  or cyan *(October)*
- borrowing the cyan-blue palettes of atmospheric references such as
  *Journey* or *ABZÛ* *(October)*

---

## 4. Lighting

Lighting should feel environmental, indirect, and atmospheric.

Prefer:

- backlighting
- rim lighting
- emissive materials
- reflected light
- fog-scattered light
- gradients
- bloom used selectively

Avoid relying on:

- realistic studio lighting
- multiple strong point lights
- game-like key/fill/rim setups
- hard shadow-map realism
- shiny PBR materials everywhere

A useful target is:

> forms are often understood first as soft shapes in the haze, then revealed through glow, motion, reflection, or proximity.

---

## 5. Materials

The material language should stay stylized and slightly unreal.

Preferred qualities:

- translucent
- ambiguous, half-formed *(October)*
- pearl, with subtle iridescence *(October)*
- membrane-like
- matte / flat-shaded
- soft fresnel edges
- emissive veins
- frosted glass-like surfaces
- wet / reflective planes
- semi-opaque particles
- low-detail faceted geometry

Materials can imply:

- tissue
- shell
- mist
- sediment
- mineral shards
- thin film
- vascular structures
- water
- soft luminous organisms

### Avoid

- photorealistic rocks
- realistic bark / leaves
- chrome sci-fi surfaces
- plastic-looking game assets
- high-frequency texture noise
- overly complex PBR detail

---

## 6. Geometry Language

Procedural geometry should feel **grown, accumulated, eroded, stretched, folded, drifted, or sedimented**.

Useful geometric families:

- basins
- channels
- membranes
- arches
- thin shells
- ribbons
- filaments
- roots
- branching structures
- suspended fragments
- clustered particles
- layered planes
- smooth low-poly landforms
- soft asymmetrical organisms

Procedural systems should not default to conventional examples.

For example:

- L-system → not necessarily a tree
- erosion → not necessarily rocky mountains
- voxels → not necessarily Minecraft terrain
- agents → not necessarily visible humanoid NPCs
- settlements → not necessarily houses and roads

Translate the underlying procedural logic into the Residual Ecology visual language.

Forms should emerge from accumulated matter and their surroundings rather
than stand on them as separate objects, so that the landscape reads as
interconnected *(October)*.

---

## 7. Atmosphere

Atmosphere is a structural part of the world, not decoration.

Core devices:

- exponential fog
- layered haze
- drifting motes
- slow spores
- suspended micro-particles
- subtle water movement
- long-period environmental pulses
- distant silhouettes
- occasional volumetric shafts
- soft bloom
- restrained grain / vignette if useful

The atmosphere should create:

1. depth
2. uncertainty
3. scale
4. presence
5. slow temporal change

---

## 8. Water / Ground Relationship

When water is present, it should behave as a **boundary and perceptual surface**, not just scenery.

Preferred qualities:

- shallow reflective water
- slow tide-like displacement
- soft fresnel reflection
- luminous trails reflected on the surface
- partially submerged geometry
- channels and basins
- surfaces that blur the distinction between sky, ground, and reflection
- luminous water and air in the spirit of *Journey*: soft light, delicate
  reflective patterns, openness, immersion, in lavender and pearl rather
  than cyan *(October)*

Ground can feel sedimentary, eroded, soft-edged, or partially dissolved into water.

---

## 9. Motion Language

Motion should communicate the nature of a system.

Possible signatures:

- **accumulation** → settles / thickens / gathers
- **return** → loops / revisits / circulates
- **fragmentation** → separates / drifts apart / destabilizes
- **growth** → extends / branches / propagates

More generally:

- wind → bends / redirects
- water → carries / deposits
- migration → leaves paths
- decay → fades / collapses / disperses
- culture → repeats / accumulates / imprints
- memory → reappears / reinforces

Avoid random motion that does not express system behavior.

---

## 10. Composition

Scenes should usually have a clear spatial hierarchy.

Prefer:

- one dominant distant landmark
- converging terrain or channels
- foreground silhouette framing
- large quiet areas
- asymmetrical compositions
- visible depth layers
- sparse focal glow
- enough negative space for atmosphere to read

Avoid filling every region with procedural detail.

The world should feel larger than the amount of geometry actually rendered.

---

## 11. Interface Language

The interface should remain minimal and subordinate to the world.

Prefer:

- world-space cues
- subtle labels
- short fading text
- quiet parameter controls in dev mode only
- interaction communicated by motion / glow / sound / spatial response

Avoid:

- large HUDs
- dashboard layouts
- persistent panels in the final experience (the current Explore panel is a
  working interface, not the final experience)
- game quest markers
- heavy instructional overlays
- generic glassmorphism UI layered over the world

For weekly technical experiments, `lil-gui` or similar controls are fine as **development tools**, not part of the final aesthetic.

---

## 12. Procedural Translation Rule

Every procedural assignment should answer two questions:

### A. What rule generates the system?

Examples:

- noise
- field
- attractor
- erosion
- growth grammar
- agent state
- evolutionary pressure
- resource distribution

### B. How would that rule manifest inside Residual Ecology?

The second question is essential.

A procedural system should not keep the visual conventions of the tutorial by default.

Examples:

| Technique | Generic Result | Residual Ecology Translation |
|---|---|---|
| Noise terrain | mountains | estuary basins / soft sediment fields |
| Erosion | rocky valleys | channels / scars / exposed luminous layers |
| Vector field | arrows / particles | spores / mist / migration currents |
| L-system | tree | membrane colony / vascular growth |
| Voxels | block terrain | porous sediment / crystalline habitat |
| Evolution solver | creature variations | membrane organisms with environmental phenotypes |
| Agents | NPC crowd | hidden organisms whose movement leaves traces |
| Settlement system | city grid | clustered structures grown around flows / resources |
| Cultural simulation | labels / stats | repeated rituals leaving spatial residue |

## 13. Aesthetic Constraints for AI Coding

When using Codex / Claude Code / Cursor, preserve these constraints unless explicitly overridden:

1. Do not introduce a new color palette casually.
2. Do not add realistic assets to make the scene feel “finished.”
3. Do not add bright UI to explain weak visual logic.
4. Do not increase speed to make the scene feel more active.
5. Do not add visual noise just because the system can generate more.
6. Prefer shader / field / instancing solutions over asset-heavy realism.
7. Preserve atmospheric depth even in technical prototypes.
8. Keep procedural parameters semantically meaningful.
9. Each procedural system should have a readable visual signature.
10. Small assignments may be incomplete technically, but should still belong to the same visual universe.
11. Do not fix a muddy or washed-out scene by making it darker or bluer *(October)*.

---

## 14. Quick Review Checklist

Before considering a weekly experiment visually acceptable, check:

### Mood
- [ ] Does it still feel dreamlike and softly luminous?
- [ ] Is the scene calm enough?
- [ ] Does it feel like a place rather than a tech demo?

### Color
- [ ] Is the palette still violet / lavender / lilac / pearl dominant?
- [ ] If mint is used, is it rare and meaningful?
- [ ] Did a fix make the scene darker or bluer?
- [ ] Did procedural generation introduce accidental rainbow colors?

### Motion
- [ ] Is motion slow enough?
- [ ] Does motion communicate system logic?
- [ ] Are transitions gradual?

### Geometry
- [ ] Has the tutorial trope been translated into this world?
- [ ] Are forms stylized rather than photorealistic?
- [ ] Is there enough negative space?

### Atmosphere
- [ ] Is depth visible through fog / haze / layering?
- [ ] Are far objects quieter than near objects?
- [ ] Is there a clear luminous hierarchy?

### Procedural logic
- [ ] Can I explain what parameters generated this state?
- [ ] Can the same rules produce meaningful variation?
- [ ] Does this system have the potential to influence another system later?
